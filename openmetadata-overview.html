The Open Context Layer for AI

让 AI 理解数据，而不只看表面

OpenMetadata 不是简单的“数据目录”。它把数据资产、血缘、治理、质量、语义、所有者、事件、记忆 和 AI 能力整合成一个统一的上下文图谱，让企业数据真正能被人和 AI 共同理解、信任和使用。

它解决的核心问题

What makes it different

AI 需要上下文

仅仅拿到仓库、表和字段，还远远不够。AI 还需要知道这份数据代表什么、谁负责、它的质量如何、上下游影响是什么。

企业知识经常丢失

很多结论、假设和修复记录都埋在聊天、文档和Ticket里，缺少统一治理与复用能力。

数据需要“被信任”

OpenMetadata 把数据质量、信任信号、政策、数据契约、版本和归属整合起来，帮助 AI 判断“这份数据值得用吗”。

五大能力

Context + Semantics + Memory + Graph + Activation

1. Context

  • 数据库 / 表 / 字段 / 看板 / 数据集
  • 质量 / freshness / ownership / 风险
  • 技术元数据和使用状况

2. Semantics

  • Glossary / 分类 / 术语 / 域
  • 数据产品 / 政策 / 业务语义
  • 把技术名词翻译成业务含义

3. Knowledge Graph

  • 资产之间建立关系
  • 列、表、团队、指标、政策互联
  • 让系统具备“关联推理”能力

4. Memory

  • 决策、假设、修复说明、事故经验
  • AI thread / runbook / tribal knowledge
  • 知识不再消失于聊天记录

5. Activation

  • MCP / Semantic Search / API / SDK
  • 供 AI assistant 与应用直接调用
  • 让上下文真正可行动

一句话总结

它不是让 AI 读数据库，而是让 AI 读懂“数据为什么重要、谁依赖它、它能不能信任、它的业务意义是什么”。

上下文与记忆图谱：六步链路

README architecture
1

Collect

从数据仓库、BI、消息系统、流水线、模型、API 等收集元数据与事件。

2

Normalize

统一 schema 和标准，形成一致的知识表达。

3

Connect

把表、列、团队、质量、标签、血缘、合同、术语绑定成一张图。

4

Preserve Memory

保留会话、决策、事故修复和经验，让组织知识可复用。

5

Govern

用分类、政策、角色、质量、评审和数据契约，让上下文保持可信且符合规则。

6

Activate

通过搜索、MCP、API、AI SDK 把上下文交给人和 Agent 使用。

AI 实际能获得什么上下文

不仅是表结构

技术元数据

库、表、字段、看板、Pipeline、API、模型及其结构。

质量与信任

测试、Freshness、画像、告警、事故和质量历史。

血缘与影响

表级、列级、看板、指标、模型的上下游依赖。

业务语义

术语、指标、KPI、分类、域、标签和数据产品。

治理规则

负责人、Steward、角色、政策、认证和数据契约。

组织记忆

对话、决策、假设、Runbook、修复记录与经验。

开放标准

DCAT、DPROD、PROV-O、OpenLineage、ODCS 与 JSON-LD。

一个直接连接数据库的 AI 只能看见结构；接入 OpenMetadata 后，它还能判断业务含义、可信度、政策边界、变更影响，以及组织已经积累的经验。

MCP 与 AI SDK：Agent 可以做什么

可检索，也可受控地行动
01

按语义搜索

例如找到“可信但有近期质量问题的客户购买数据集”。

02

理解资产详情

读取描述、负责人、术语、分类、质量、使用情况与契约。

03

追踪血缘与影响

分析列变更会影响哪些看板、Pipeline、指标或模型。

04

保存与复用记忆

把事故调查、修复方案、决策和业务解释沉淀为可治理知识。

05

辅助治理

建议描述、术语、敏感数据分类、负责人和契约上下文。

06

自动化数据质量

创建测试、归纳失败、定位根因、保留修复记忆并提出下一步。

仓库里关键模块

Project structure
Backend

openmetadata-service

Java 后端，提供 REST API、Repository、搜索、迁移和核心业务逻辑。它是整个项目的中枢。

Frontend

openmetadata-ui

React + TypeScript 前端，负责展示目录、搜索、治理、线索和资产详情等页面。

Ingestion

ingestion

Python 采集层，从不同数据源拉取元数据并通过 API 写回后端。

Schema

openmetadata-spec

JSON Schema 是项目的“真相源”，Java / Python / TypeScript 代码都由它生成。

Search

Search / Index

通过 Elasticsearch / OpenSearch 提供语义和结构化搜索能力。

AI

MCP / SDK

让 AI assistant 和 Agent 能以标准化方式访问数据上下文和记忆。

UI Lib

openmetadata-ui-core-components

统一按钮、表格、表单和设计 token 等前端组件能力。

Ops

docker / conf / bootstrap

包含本地开发、部署配置、数据库迁移和基础设施运行方式。
